## 1. 总体方案

采用 **Tauri 2 + Vue 3/TypeScript + Fluent UI Web Components + Rust**，实现“拖拽设计 → 配置串口和协议 → 连接流程及插入代码块 → 数据绑定 → 预览调试 → 导出独立程序”的完整流程。

已确定的范围：

- **交付平台**：Windows 10/11 x64，以及 macOS 14+ Apple Silicon arm64 / Intel x64；设计器、独立运行程序和协议插件按目标分别构建。当前仅在本机实际可用环境验证，不以架构检查代替其他架构实机验收。
- **使用方式**：工程师通过低代码搭建界面和流程，开发者通过 Python 代码块补充业务计算、通过协议插件扩展设备协议。
- **首版通信**：串口。
- **交付形式**：包含 UI、通信后端、协议插件及运行依赖的独立运行包。
- **交互逻辑**：首版包含基础流程节点、Python 代码节点、数据绑定和轮询；协议组帧、解析及设备事务仍由协议插件实现。

```mermaid
flowchart LR
    A[界面与流程设计器] --> C[共享界面渲染与项目模型]
    B[独立运行程序] --> C
    C <-->|操作与数据| D[Rust 通信与流程运行核心]
    D <-->|收发字节| E[串口设备]
    D <-->|JSON-RPC| F[协议插件进程]
    D <-->|JSON-RPC| G[按需启动的 Python 执行进程]
```

设计器和运行程序共享渲染模块、项目模型及 Rust 通信与流程运行核心，确保预览与发布后的行为一致。流程编辑体验借鉴 Node-RED，采用自有轻量执行器；首版不承诺兼容 Node-RED 流程文件、运行时 API 或第三方节点包。

## 2. 设计器与用户操作

### 工作区布局

v0.9 根据用户确认的紧凑专业工具方向，优化界面主窗和独立逻辑窗，以增加画布空间并减少固定栏位。原有顶栏、命令栏和工作区标签合并为 48px 工具栏；保留项目名称、保存、撤销/重做、逻辑窗口、检查、预览及导出入口。窄窗将检查和导出收进“更多操作”；设计器语言、侧栏显隐、恢复默认布局和帮助位于“工作区设置”，工程语言位于“文件”。画布上方 34px 上下文栏提供复制副本、删除、对齐/等距/等尺寸及页面或容器布局操作。

组件库采用约 30px 单行条目、可折叠分组和固定搜索，仍支持拖拽释放定位、点击后放置、Esc 取消、图层和页面管理。属性保留“属性 / 绑定 / 事件”，常用内容及几何信息默认展开，外观、约束、自定义业务属性和共享动作管理按需展开。属性搜索覆盖全部分组，支持中英文标签及字段标识，命中时展开对应分组，清空后恢复原折叠状态。逻辑窗节点库采用紧凑分组和搜索，Python 编辑区利用剩余高度，执行限制、帮助与执行详情按需展开。

底部设备连接、项目变量、执行记录、检查与状态合并为 32px 资源栏，默认收起；点击标签展开，再次点击当前标签收起。添加串口控制面板自动打开设备连接；用户主动检查或预览遇到错误时展开检查，后台问题仅更新计数。设备基本参数直接可见，高级串口和协议参数折叠；变量可按名称或 ID 搜索。

左右侧栏默认 220/300px，展开资源面板默认 240px；拖动分隔条可调整尺寸。有效尺寸随视口收缩，800×600 保留至少 320px 中央工作区宽度，缩窗不覆盖用户首选尺寸。布局尺寸、显隐、底栏标签和展开状态按 main/logic 窗口分开保存在本机 localStorage（`hmi.studio.layout.v1.*`），损坏或不可写存储安全回退；“恢复默认布局”仅重置当前窗口。布局偏好不写入工程，不产生撤销记录、未保存状态或预览热更新。

本次不改变工程 schema、Rust IPC、预览/Runner 界面或用户设计控件的运行样式。布局验收覆盖 1920×1080、1366×768、800×600、中英文及两个编辑窗口；1366×768 默认布局下画布可滚动高度相较调整前增加至少 150px。实际测量、回归结果与原生环境限制记录在 [VERIFICATION.md](VERIFICATION.md)。

界面设计主窗与逻辑流程原生窗口可同时编辑同一工程。两个编辑窗通过 Rust WorkspaceStore 提交按稳定对象 ID 定位的操作，各窗口拥有独立撤销/重做历史；同字段并发冲突及破坏他窗新增引用的撤销整笔拒绝，不回滚另一窗口修改。关闭逻辑窗保留工程会话与其历史；关闭主窗处理整个工程退出。

点击“预览运行”启动独立 Runner preview-host 子进程及原生预览窗口，由子进程拥有 Rust 执行核心、串口、插件和 Python；重复打开只恢复并聚焦现有进程。预览运行期间两编辑窗保持可编辑，修改停顿 300 毫秒后自动校验并发送候选版本，失败继续最近有效版本；预览状态显示已应用修订号、等待和校验问题。

每个已启动任务捕获不可变项目版本，旧任务按旧逻辑完成，新触发使用新版，并保持同流程单飞。普通界面、流程与 Python 源码更新不重启预览进程；串口配置、变量删除/类型/枚举值域或 Python 环境配置变更暂停新触发，等待既有任务及事务收尾后切换，不排队、不补发。关闭主窗或控制通道断开时预览子进程也停止并清理资源。

前端使用 Vue 3 Composition API、TypeScript、Vite；画布采用 DOM 绝对定位，使用 `vue3-moveable` 实现移动、缩放和吸附，使用 `vue3-selecto` 实现框选。

流程编辑采用 [Vue Flow](https://vueflow.dev/guide/)（`@vue-flow/core`，MIT；本次核实版本 1.48.2），支持节点拖拽、端口连线、缩放和选择，节点外观与参数面板使用统一 Fluent 设计令牌。Vue Flow 只负责编辑和执行状态展示，实际调度由 Rust 完成。

### Vue 与 Fluent Design 组件库

- 选用微软官方的 [Fluent UI Web Components](https://github.com/microsoft/fluentui/tree/master/packages/web-components)，包名为 `@fluentui/web-components`，采用 MIT 许可。使用 3.x API，本次核实的稳定版本为 3.1.3；实施时从该版本开始验证并提交依赖锁文件。
- 该库基于 Web Components，按 [Vue 自定义元素集成规则](https://vuejs.org/guide/extras/web-components.html) 接入。在 Vite 的 Vue 插件编译配置中，将 `fluent-` 前缀识别为自定义元素，按需注册所用组件。
- 建立共享 Vue 适配层，统一控件属性、类型、事件和 `v-model`；输入框、下拉框、开关的值通过 DOM 属性及原生事件映射，避免将复杂值序列化为 HTML 字符串属性。
- 按 3.x 当前接口配置主题和设计令牌；设计器、预览和 Runner 共用组件适配层及主题，确保字体、间距、颜色、焦点和禁用状态一致。依赖和主题资源均本地打包。
- Fluent 组件用于按钮与表单；菜单、对话框及数值显示、状态灯、曲线和日志等专用界面通过 Vue/HTML 实现，并使用相同 Fluent 设计令牌。
- 依赖核实来源：[npm 包元数据](https://registry.npmjs.org/@fluentui%2Fweb-components)、[当前官方接入与主题说明](https://github.com/microsoft/fluentui/blob/master/packages/web-components/README.md)。旧版接入示例须核对 3.x API 后使用。

### 首版设计能力

- 多页面共用项目设计尺寸，尺寸可配置，默认 1280×720；运行时等比缩放、居中显示。
- 控件拖放、调整尺寸、多选、对齐、复制、删除、层级调整、撤销和重做。
- 基础控件：文本、按钮、输入框、数值显示、下拉框、开关、状态灯、分组框、实时曲线和日志面板。
- 属性配置覆盖位置、尺寸、字体、颜色、标题、数值格式。
- 图片和字体随项目保存，运行时不依赖在线资源。

### 串口组件的操作体验

“串口连接”属于非可视资源，可以被多个控件共用；同时提供可直接拖入页面的“串口控制面板”。

典型操作：

1. 添加串口连接，设置端口、波特率、数据位、停止位和校验。
2. 为连接选择协议插件，并填写插件提供的设备参数。
3. 添加按钮，将点击事件绑定到流程入口；简单操作可以直接选择“打开连接”“关闭连接”或某个协议命令，设计器将其保存为单动作流程。
4. 在流程工作区连接命令、条件、赋值等节点，需要自定义计算时插入 Python 代码节点，并按需配置 Python 依赖。
5. 将数值、状态灯和曲线绑定到协议数据点或项目变量，并配置命令参数，例如从输入框读取目标值。
6. 进入预览并显式启动流程，连接真实设备，检查节点输入输出、执行路径、返回数据和通信日志。
7. 导出当前平台及架构的独立运行包。

编辑模式不执行设备操作；预览启动前完成流程校验，停止预览时取消触发器和未执行任务，并由会话管理器关闭本会话的连接与子进程。首版默认采用手动连接和故障后的手动恢复，连接操作由明确配置的连接节点执行；导出的程序保留串口设置入口，便于换电脑后重新选择端口。

## 3. 通信核心与协议插件接口

### 职责划分

| 模块 | 职责 |
| --- | --- |
| Rust 运行核心 | 串口枚举和生命周期、字节收发、插件及代码执行进程管理、流程调度、命令队列、轮询、数据状态和日志 |
| 协议插件 | 组帧、分帧、校验、设备应答关联、协议超时、数据解析及命令实现 |
| Python 执行进程 | 使用包内对应平台独立解释器执行同步业务计算和消息转换，返回结果或错误，每次调用结束后退出 |
| 界面 | 展示数据、收集输入、编辑流程、触发已声明的流程入口并展示运行状态 |

Rust 使用 Tokio 和 `tokio-serial`。每个串口连接绑定一个协议实例、启动一个插件进程；项目可以配置多个独立连接，同一端口禁止重复占用。Rust 宿主独占串口，协议插件通过宿主收发字节。

### 插件形态

协议包包含清单、配置描述、目标平台可执行文件和必要依赖。由产品自己的 Rust 插件管理器发现并启动，新增协议无需重新编译设计器；清单的 target 固定为对应 Rust 三元组，必须与宿主目标严格一致。缺少 target 的旧清单仍按 Windows x64 处理；macOS 不会直接执行 Windows 插件。导入及导出同时检查 PE / Mach-O 架构及 macOS 可执行权限。

不将 Tauri 的编译期插件机制作为用户协议扩展接口。

插件接口采用 **标准输入输出上的 JSON-RPC 2.0**：

- UTF-8 编码，每行一条消息；二进制字节使用 Base64。
- `stdout` 专用于协议消息，`stderr` 用于日志。
- 支持版本握手、初始化、接收串口字节、请求发送字节、执行命令、返回结果、发布数据点和关闭。
- 插件声明配置项、数据点、命令及参数类型，用于自动生成设计器表单和绑定选项。
- 首版提供 Rust SDK、示例协议和模拟设备；其他语言可以按同一接口接入。

### 项目与绑定接口

项目使用带 `schemaVersion` 的 JSON，记录页面、控件、连接、协议实例、绑定、项目变量、流程和资源引用；插件版本固定记录在项目中。流程记录节点 ID、类型、配置、连线端口和编辑布局，节点类型版本由项目 `schemaVersion` 统一约束，Python 代码节点保存源码。使用 Python 节点时，项目另记录所选 Python 运行资源版本、校验和以及第三方依赖锁定清单。项目变量记录类型与初始值，运行值不写回工程初值；兼容运行状态在热更新时按稳定 ID 保留。

- 数据点支持数字、文本、布尔值和枚举，并携带时间戳及有效状态。
- 控件属性可以绑定协议数据点或项目变量；按钮等业务事件引用流程入口。简单业务动作配置统一保存和执行为单动作流程，同一事件只触发一个入口，避免动作与流程重复发送命令。开始/停止控制按钮绑定独立的宿主管理操作，不经过业务流程队列。
- 节点参数可引用常量、当前消息字段、触发时的控件输入快照或执行时读取的项目变量。写设备必须通过明确配置的连接或协议命令节点触发。
- 启用状态、可见状态支持绑定布尔数据点或变量。代码仅在显式 Python 节点执行，控件属性和条件表单不另引入表达式语言。
- 同一连接的命令串行执行并等待应答；轮询统一保存为“定时触发 → 协议命令”流程，不保留独立轮询执行路径。

串口拔出、插件崩溃或通信超时必须反馈到界面。连接故障时结束待处理调用、将关联数据标记为失效；控制命令不自动重发。

## 4. 流程编排与 Python 代码节点

### 首版节点与使用示例

借鉴 [Node-RED 消息模型](https://nodered.org/docs/user-guide/messages)，节点通过消息连接业务逻辑。首版采用下列固定节点类型，协议插件提供的命令通过通用“协议命令”节点选择。

| 节点类别 | 首版能力 |
| --- | --- |
| 触发 | UI 业务事件、定时器、协议数据点值变化；流程开始/停止由独立宿主控制入口管理 |
| 连接与命令 | 打开/关闭已配置串口资源、调用协议命令并等待结果 |
| 条件 | 根据配置的字段、比较符和目标值选择 true/false 输出 |
| 消息赋值 | 将常量、字段或变量值写入当前消息，不修改其他分支消息 |
| 项目变量 | 读取变量到消息，或将结果写入变量以更新绑定控件 |
| 延时 | 异步等待指定时长，不占用串口事务锁 |
| Python | 编辑同步 `def transform(msg): ...` 函数，进行校验、计算和消息转换，可使用标准库及项目声明的第三方依赖 |
| 页面与日志 | 切换页面、输出结构化调试记录 |

示例：“读取温度”按钮 → 协议读取命令 → Python 换算 → 写入 `temperature` 项目变量 → 数值控件与曲线通过绑定更新。

```python
def transform(msg):
    import math

    raw = float(msg["payload"]["rawTemperature"])
    if not math.isfinite(raw):
        raise ValueError("温度数据无效")
    msg["payload"] = {"temperature": raw / 10}
    return msg
```

### 调度、消息与错误约定

- Rust 在预览启动及导出前校验节点类型、参数、资源引用、端口方向及连线。首版仅允许有向无环图（DAG），禁止自连接和回环；重复执行由定时触发器实现。
- 提供宿主 `flow.start(flowId)` / `flow.stop(flowId)` 管理接口，供设计器、Runner 和控制按钮调用，不受业务队列繁忙或触发器停用状态限制。预览及 Runner 启动时注册项目中已启用流程的触发器；手动恢复只重新启用触发器，不补发停止期间的事件。
- 每次接受触发创建唯一 `runId`。业务消息 `msg` 为可 JSON 序列化的对象，推荐使用 `payload` 字段；流程 ID、节点 ID、时间及追踪信息由宿主管理，代码节点不能覆盖这些运行元数据。
- 分支得到独立消息副本；多条入边每到达一条消息即执行一次，不隐式等待或合并其他分支。首版每个流程最多一个运行实例，分支按稳定连线顺序入队，运行实例逐节点执行，异步等待不阻塞其他流程。
- UI 触发遇到本流程繁忙时提示“正在执行”；定时及数据触发遇忙跳过并计数。同一连接跨流程共享 FIFO 命令队列，上限为 64 条待执行请求，满时返回可见错误，不静默丢弃控制命令。
- 首版每条业务消息上限 1 MiB，每次运行最多 1,000 次节点执行及 256 条待执行消息；单次运行默认截止时间 30 秒，可配置为有限正值。超出容量、步数或运行截止时间时直接终止本次运行并记录原因。
- 数据触发只响应实际值变化，忽略仅时间戳变化；对可追踪的本流程写入抑制自触发。每流程自动触发上限为每秒 10 次，超过时暂停该流程的自动触发并提示手动恢复，防止设备事件形成画布之外的反馈循环。
- 普通节点失败通过可选 `error` 输出传递带错误码、说明和失败节点 ID 的消息；未连接错误输出则终止本次运行并取消尚未执行的分支。异常堆栈保留在调试记录中；首版不做自动重试或设备操作补偿。
- 停止单个流程会禁用其触发器并取消尚未执行的节点、延时及排队命令，不关闭其他流程共用的串口。已发出的设备命令不回滚；连接管理器继续消费其应答或等待超时后处理事务收尾。协议插件须识别并丢弃旧事务应答，确认恢复同步后才能执行下一命令；无法可靠关联或恢复同步时，将连接标记为故障并阻止后续命令，等待手动恢复。正在执行的代码任务可终止，停止后不派发后续节点。

### Python 执行边界

- Windows 使用官方 x64 [Python embeddable package](https://docs.python.org/3.14/using/windows.html#the-embeddable-package)。首版采用常规 CPython 3.14 系列，本次核实并选定 [3.14.8 embeddable amd64](https://www.python.org/downloads/release/python-3148/)，运行资源清单固定版本及 SHA-256；不混用 free-threaded 或其他架构解释器。
- Rust 使用包内解释器（Windows 为 `python.exe`，macOS 为 `bin/python3.14`）的绝对路径及独立参数列表启动受控执行脚本，每次代码节点调用创建一个新进程，完成后退出。每项目同时执行一个代码任务，最多等待 64 项，超出时返回节点错误；不调用系统 Python、`py` 启动器或 shell 拼接命令。
- `def transform(msg): ...` 接收 JSON 对象对应的字典，返回可严格 JSON 序列化的字典时发送到普通输出，返回 `None` 时只结束当前消息分支。异常、协程、生成器、自定义对象、非有限浮点值或其他无效返回值进入节点错误处理；跨调用状态通过项目变量节点管理。
- 宿主与执行脚本使用 UTF-8 JSON-RPC 消息，协议输出专用；Python `print` 以及本地扩展的普通标准输出重定向到日志通道，避免污染消息。首版代码用于同步计算，设备访问统一通过流程连接/协议节点，逐帧解析和高频轮询结果处理优先由 Rust 与协议插件完成。
- 每次调用默认墙钟时限 5 秒，包含进程启动、模块导入、执行和结果返回，可按节点配置有限正值且受流程总截止时间约束；等待队列另计入流程总截止时间。每次独立进程可清除 Python 模块、本地扩展及线程状态，代价是启动和导入开销。
- Windows 通过 [Windows Job Object](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 管理任务进程树：挂起创建进程、加入 Job 后恢复，设置 `KILL_ON_JOB_CLOSE`，禁止逃离 Job。默认 Job 提交内存上限 256 MiB，可按节点配置；内存分配失败、进程退出、取消和超时均映射为可见节点状态，超时或取消时终止整个 Job 并回收资源。内存限制约束提交内存，不能当作 Python 堆或实际驻留内存上限，也不假定触限会立即杀进程。
- Windows 使用 `python314._pth` 显式限定标准库、执行器和项目依赖目录，默认不启用 `import site`，避免受到系统 Python、注册表和环境搜索路径影响。`._pth` 和 Job Object 用于依赖及生命周期管理，不是权限安全沙箱；Python 按当前用户权限执行，首版面向可信项目代码。

### Python 按需打包与依赖

- 以导出项目是否包含 Python 节点决定是否打包代码节点运行资源：没有 Python 节点时，不额外附带对应平台解释器、执行脚本或第三方包；只要存在 Python 节点，即使所在流程暂未启用，也随包携带一份固定版本解释器及执行资源。协议插件自身的依赖仍按插件清单完整发布，不由此规则裁剪。
- 保留对应平台独立 Python 分发中的完整必要运行文件和标准库，不根据源码 `import` 文本逐文件裁剪标准库。第三方依赖按显式声明和锁定清单准备其完整传递依赖，包含包名、版本、目标 ABI/平台及文件校验和。
- Windows embeddable 包不包含 pip，官方不支持按普通 Python 安装方式用 pip 管理该分发的依赖。第三方库由开发/构建环境中的标准 Python 与 pip 准备为可离线导入的依赖包；设计器负责导入和校验这些预构建资源，Runner 不在线下载或运行 pip。
- Windows 依赖准备只接受与 CPython 3.14、`win_amd64` 匹配或明确兼容的 `abi3` / 纯 Python wheel，解析并锁定传递依赖，随包展开到项目专属依赖目录；不在导出时现场编译源码包。原生 `.pyd`、附属 DLL 和许可文件一并验证，版本冲突或缺失时阻止导出。
- 设计器通过已校验的本地缓存或离线导入包获得解释器和依赖，预览与导出使用相同版本、锁定清单和路径布局。缺少所需资源时提示准备或导入，不能回退到系统解释器；依赖的准备方式参考 [pip 目标平台下载规则](https://pip.pypa.io/en/stable/cli/pip_download/)。
- 默认关闭 site 初始化；依赖 `.pth` 可执行初始化或特殊加载逻辑的库必须先适配验证。包可用性检查在受限时的独立进程中导入已声明模块，并检查缺失 DLL；不能以 wheel 下载成功替代运行验证。

### 编辑、预览与发布一致性

- 设计器提供节点参数与代码编辑、连线校验、当前节点状态、输入输出检查和按 `runId` 查询的执行路径、耗时及错误。首版不提供断点、单步调试或热修改正在运行的流程。
- 预览启动时创建带资源快照的独立运行子进程，后续校验通过的工程修订自动热更新；运行中的任务继续持有旧版本。若会话已启动而首次状态读取失败，仍保留预览窗口及停止/重试入口。预览与 Runner 调用同一个 Rust 执行核心，业务流程不在 WebView 中执行。
- 新增流程格式和节点版本属于项目模型的一部分；首次实现时确定项目 `schemaVersion`，此后格式变化提供显式版本检查和迁移。代码预检使用 Python AST/编译检查语法及同步 `transform(msg)` 入口形状，不执行用户源码中的导入、函数或设备操作。导出缺失节点类型、无效代码或无效连接的项目时，阻止发布并定位到节点。

### macOS 运行资源与进程边界

- macOS 使用维护方 python-build-standalone 的固定 CPython 3.14.8 regular install-only 分发（release `20261013`），分别锁定 arm64 / x64 下载 URL 和 SHA-256，资源来源记录于 `resources/python/`。Python 官方 Windows embeddable ZIP 不用于 macOS。
- macOS Python 资源 ID 为 `3.14.8-aarch64-apple-darwin` / `3.14.8-x86_64-apple-darwin`，使用包内 `bin/python3.14`；独立参数与隔离搜索路径确保不调用系统 Python。依赖按目标平台及架构锁定，预览与发布使用相同环境。
- macOS 每次调用使用独立进程组，超时、取消、调用结束或宿主丢弃调用时终止组内后代。按约 100 ms 间隔采样进程组的 RSS 合计，超出节点配置后终止进程组并返回可见错误；这是有采样间隔的驻留内存检测，允许短时超额，不能承诺 Windows Job 的提交内存硬限制。进程组及路径隔离不构成权限安全沙箱。
- Windows / macOS 的 Python 资源、协议插件和第三方原生依赖不能混用。跨平台项目仍可编辑；显式导入对应平台运行资源或依赖后更新项目运行资源配置，不静默转换已有依赖锁。

## 5. 独立程序生成与兼容性

采用**预编译 Runner 模板组装发布**，无需用户现场编译。流程为“校验项目、流程及代码 → 检查对应平台插件与按需 Python 资源 → 复制 Runner → 加入项目与资源 → 生成完整校验清单 → 打包”。只导出当前宿主平台及架构的运行包。

| 目标 | Rust target | 交付及 WebView |
| --- | --- | --- |
| Windows 10/11 x64 | `x86_64-pc-windows-msvc` | ZIP 运行目录、`HmiRunner.exe`，携带固定 WebView2 |
| macOS 14+ Apple Silicon | `aarch64-apple-darwin` | ZIP 内 `HmiRunner.app`，使用系统 WKWebView |
| macOS 14+ Intel x64 | `x86_64-apple-darwin` | 独立 x64 `.app` ZIP，使用系统 WKWebView；不与 arm64 合为 universal 包 |

- 对应平台的构建宿主生成设计器、Runner、CLI 和示例协议插件；`scripts/build.ps1` 保留 Windows 路径，`scripts/build-macos.sh` 提供 macOS 原生构建。macOS 最低系统版本和 deployment target 固定为 14.0，最低系统及 Intel 验收须使用对应机器完成。
- Windows 沿用固定 WebView2 155.0.4283.45 x64 分发；macOS 使用系统提供的 WKWebView，不复制或检查 WebView2；Fluent UI 3.x 的下拉框直接使用 Popover 等现代 Web API，因此最低系统基线设为 macOS 14，较旧 macOS 需要另做兼容适配（参见 [WebKit Safari 17 特性说明](https://webkit.org/blog/14445/webkit-features-in-safari-17-0/)）。Windows 10 固定运行时目录权限仍遵循既有分发要求。
- Windows 模板位于 `templates/windows-x64`；macOS 模板位于 `templates/macos-arm64` / `templates/macos-x64`，包含无项目运行资源的 `HmiRunner.app`。项目、插件、图片字体和按需 Python 放入最终 app 的 `Contents/Resources`，通过可执行文件位置解析，不依赖当前工作目录。
- macOS 导出保留可执行权限；拒绝模板夹带旧项目和运行依赖，资源组装后重新 ad-hoc 签名并验证，再生成完整文件校验清单。开发构建不包含 Developer ID 签名或 Apple 公证；跨机器分发验收须明确这一状态。
- macOS Studio 从 app 内资源初始化当前用户的可写资源缓存，资源导入不改写已签名的设计器 app。Runner 将项目作为只读发布内容，端口选择、窗口设置及日志写入当前用户目录，并按项目 ID 隔离。
- 无 Python 节点时不附带代码节点解释器；含 Python 节点时仅附带匹配当前平台和锁的独立解释器、执行脚本及完整依赖，不在目标机器安装或运行 pip。协议插件的私有依赖仍按插件清单完整携带。
- 缺少模板、所需插件/Python/依赖/资源，平台、架构、ABI 或版本不匹配，绑定、流程或源码校验失败时阻止导出。项目 `schemaVersion` 继续为 1，资源 ID 和插件 target 显式区分平台。
- Runner 支持 `--project` 指定绝对项目路径。首版支持自定义窗口标题；图标与原生版本信息沿用各平台模板。
- 串口仍由 Rust 统一管理，macOS 枚举 `/dev/cu.*` 等系统串口路径。设备驱动、当前用户权限及真实设备时序须在目标机器验收，软件模拟不替代硬件验证。

Linux 及其他平台或架构仍不在交付范围；后续扩展通过新的方案变更确定。

- **流程执行**：覆盖条件分支、消息副本隔离、多入边独立触发、错误输出、重复点击、队列满、步骤/消息/时间限制、数据触发反馈，以及繁忙/停用状态下的宿主停止与恢复；验证多个流程共享串口时的应答关联、取消后事务收尾、迟到应答丢弃及无法恢复同步时的连接故障处理。
- **代码节点**：覆盖正常转换、`None`、语法错误、异常、协程/生成器和不可序列化返回值、死循环、阻塞、内存分配失败、进程异常退出及跨调用状态隔离；验证宿主仍可操作、取消后子进程回收，以及 Python/native 标准输出不污染协议。
- **项目与发布校验**：覆盖流程保存重开、源码保持、节点版本、悬空连线、禁止回环、资源引用错误及无效代码；预览与 Runner 执行同一项目得到相同输出。
- **Python 按需发布**：无 Python 节点的包不额外携带代码节点解释器；含节点的包只带一份匹配解释器与执行资源。覆盖禁用流程仍含代码节点、纯标准库、第三方包及传递依赖、原生 DLL、ABI 不匹配、依赖冲突、缺失资源和 site 初始化依赖；确认预览与导出使用同一锁定环境，离线运行无需 pip，协议插件自带依赖不被误删。
- **独立部署**：无 Rust、Python、Node.js、Node-RED 和设计器的 Windows 10/11 x64 与 macOS 对应架构环境中离线运行，验证中文路径、空格路径、更换端口以及插件/Python 资源缺失或架构不匹配时的导出拦截；另验证已安装其他 Python 或设置 `PYTHONPATH` 时仍使用包内解释器和依赖。
- **完整演示**：用示例设备完成打开串口、读取数值、代码换算、条件判断、变量绑定显示曲线、写入参数、停止流程及关闭串口，并验证异常恢复。

首版包含上述固定流程节点与同步 Python 代码块，扩展插件仅开放协议类型；不包含自定义 UI 或流程节点插件、Node-RED 兼容层、任意图回环、同步分支汇合、异步 Python 节点、终端在线 pip 安装或源码依赖现场编译、TCP/UDP、历史数据库、报警配方、插件热更新及应用工程源码生成。完成上述闭环后，再沿现有连接、协议和流程接口扩展。

## 8. v0.8 工程与设计交互扩展

### 完整工程包

保存与另存为统一生成 `.hmiproj`（ZIP 容器，包格式版本 1），内部项目模型为 schemaVersion 2，包含清单、完整页面/流程/Python 源码、图片字体、多语言和工程使用的已导入插件及 Python 解释器/依赖。资源按平台 target 分变体，文件均有大小与 SHA-256，保留可执行权限。未导入的目标依赖标明缺失，不自动下载；不完整业务草稿允许保存，资源损坏不能覆盖有效包。独立运行程序仍由“导出程序”生成按目标平台的 Runner 包。

打开包先检查安全路径、文件集合、摘要、权限及配额，然后展开到用户可写工作副本。新建工程在首次保存前即可导入资源；保存以一致修订快照写临时包后原子替换，期间新编辑仍保持未保存。工作副本保留恢复信息。旧 JSON 仅作为导入兼容，迁移收集相邻资源，保存时保留原文件并生成工程包。浏览器设计模式采用相同归档格式并透传已有平台二进制资源。

### 组件、属性与布局

保留原有组件，新增工具按钮、多行文本、复选/单选、数值输入、滑块、日期时间、图片、进度、列表、树、可编辑表格、面板、滚动区、选项卡、堆叠页、分隔面板、对话框、菜单、工具栏、状态栏、分隔线和弹性空白。属性由共享 catalog 描述，支持分组搜索、多选编辑、恢复默认、绑定/事件及有类型动态业务属性；共享动作可在按钮、菜单和工具栏复用。

控件列表保留稳定 ID，通过 parentId/slotId 形成容器树，布局支持绝对、水平、垂直、网格和表单，包含间距、尺寸约束、伸缩、对齐与跨格。设计器、预览和 Runner 使用同一渲染与布局模块。v1 导入后页面继续等比缩放且不自动分组；新布局页面可自适应窗口。

### 画布和右键交互

组件和流程节点均在拖拽释放位置创建，拖动显示预览；点击组件库进入放置模式，再点击画布定位。坐标换算处理缩放、滚动与容器偏移，自动布局按落点插入；无效区域或 Esc 取消，不创建对象，一次投放一笔撤销。

画布支持六向对齐、等距分布、等宽等高、标尺和可持久化辅助线；吸附以屏幕距离保持各缩放手感一致。普通滚轮在画布以指针为中心缩放（10%～400%），Shift+滚轮水平平移，空格/中键拖动平移，侧栏滚轮只滚内容。菜单按空白画布、对象、多选、容器、页面、流程节点/连线及属性上下文显示，新建/粘贴使用右键位置，右键保留已有多选；文字与代码编辑保留原生菜单。菜单、工具栏和快捷键复用同一操作与独立撤销。

侧栏与底栏可调尺寸及收起，内容不足时分别滚动，宽表格和代码支持横向滚动；窄窗口关键操作可达，按 800×600、不同 DPI 和长文案验证。

### 多语言

设计器首批提供简体中文和英文，两编辑窗同步设置。工程语言表可新增语言、设默认语言、编辑和导入/导出 JSON/CSV；组件文案、提示、菜单和表头用稳定词条键，缺失时回退到默认语言及原始文本。设计器语言与运行语言分别配置；预览/Runner 可运行时切换，翻译修改热更新，不重启会话，设备数据和源码不自动翻译。

### 实施与兼容

应用版本升级为 0.2.0，项目格式 v2；新应用兼容导入 v1，旧应用不承诺读取新工程包。当前 Windows/macOS 目标和 Python 离线执行边界不变。工程服务、组件布局、多语言和进程热更新按逻辑条目留痕，真实验证及尚未完成项目见 [VERIFICATION.md](VERIFICATION.md)。


## 10. v1.0：PTB 示例与可复用设备能力

按用户确认实现 `07-gui` 当前界面及 C1–C7 协议，交付 Windows x64 的可编辑 `.hmiproj`、独立运行 ZIP 与后端源码。主界面保留左侧统计/设备表、右侧日志、底部状态，每设备一个独立原生设置窗口及六个左侧页签；同设备再次打开聚焦现有实例。新界面由通用控件与可编辑流程定义。

新增文件选择、连续字节选择和内存范围图，扩展表格动作/徽标/文件列、左侧页签和结构日志，并提供属性、绑定及事件编辑。增加 schema 3 的后端实例和窗口模板、后端事件/调用节点、上下文绑定、窗口与文件操作。新应用读取 v1/v2；旧 Runner 拒绝 schema 3。应用升级至 0.3.0，温度示例及既有串口接口继续保留。

USB Printer 不套用串口连接接口：新增独立后端提供程序，使用 .NET 10 NativeAOT 提取参考 C# 协议、配置、固件及 USB 代码，Rust 负责生命周期、资源和调度。真实 USB 与模拟模式显式隔离，默认模拟；任务返回 jobId 并发布进度，同设备事务串行、不同设备并行。PTB demo 没有 Python 节点，不捆绑 Python。

沿用当前 GUI 的配置序列化、CRC 和 C1–C7，不自动兼容旧 MCU 协议变体。C1/C3/C7 禁止自动重试；取消须收尾已发请求，无法确认响应归属时隔离会话并要求明确设备恢复。停止查询不表示物理停止。文件通过已校验快照引用交付后端，配置与固件可携带导出。后端与资源变更进入收尾屏障，普通 UI 保持热更新。

设备 ID 页提供继续 C2 查询和确认物理复位后的恢复入口。C6 回读头载入草稿，保留本地固件引用和 DUT 设置，应用后持久化。日志保留 1000 条并支持每日自动导出；快照超消息预算时明确标记截断。USB 拓扑采用 650 ms 枚举轮询，暂未接入原 GUI 的 WM_DEVICECHANGE 通知；该实现差异及真实热插拔验证边界纳入验收记录。

详细接口、操作及可复现构建见 [ING-PTB.md](ING-PTB.md)。真实 USB/烧录和目标系统验收以实际验证记录为准，不能用模拟测试替代。
