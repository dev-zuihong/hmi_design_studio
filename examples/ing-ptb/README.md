# ING PTB 可编辑示例

`project.json` 是 schemaVersion 3 工程。主界面和设备设置页由通用组件、数据绑定及流程节点组成，可在设计器中修改；`device_settings` 窗口按设备键创建独立实例，共享同一后端会话。

- 默认后端模式为 `simulation`，自动建立三个模拟设备。实际 USB Printer 模式由工程后端资源中的模式字段选择。
- 行内按钮启动任务、停止后续查询或打开设备设置。停止查询不保证设备上的物理任务停止。
- 设置修改进入设备草稿；“应用”保存草稿，“下发配置”执行验证、应用和下发。只有地址重叠这一项仍需确认时才显示确认对话框。
- 产品固件支持五个槽位，测试固件使用独立槽位；文件通过运行器导入为资源快照。配置导入和导出保留伴随固件文件。
- 滚码支持 4–32 字节、连续位域和 52 次预览。RF、滚码、固件内存分布及设备读回结果都来自后端状态。
- “实时导出”控制后端的每日业务日志文件，目录由后端报告；“导出”可另存当前日志。
- 设备 ID 页可继续查询已启动任务的结果；遇结果未知或不完整传输，实际复位设备后使用“复位后恢复连接”。恢复会要求确认，重开 USB 句柄不等于设备复位。

`assets/simulation-sample.bin` 和 `.hex` 是确定性的测试字节，**不是可用于产品的实际固件**。默认工程不选择这些文件，产品固件操作默认关闭；`sample.ptbcfg` 也保持产品固件关闭。实机操作前须选择相应产品的正确固件和参数。

在仓库根目录运行 `node scripts/generate-ptb-demo.mjs` 可重新生成工程和测试资源。隐藏流程 `flow_scan` 供包验证使用，不在参考主界面中添加批量工具栏。生成脚本是示例的维护源；直接修改生成的工程后，再生成会覆盖这些修改。

界面结构依据 ING PTB 参考主窗口与设备设置窗口迁移。实际设备、USB 驱动和目标板验收另行执行，模拟测试不替代实机验证。
